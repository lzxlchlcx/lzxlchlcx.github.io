# 交互球体设计经验

发光镂空球体的视觉层次来自不规则孔洞、深色骨架、彩色透光膜和内部光源的配合。将几何、材质、运动和人物素材分别控制，才能有针对性地调整外观，并让球体承担导航交互。

这里的实现经验来自 [orb.js](orb.js)，素材目录与独立预览入口见 [素材说明](README.md)。其中“现有实现”描述代码已经采用的做法，“复用流程”和“排查顺序”用于指导后续设计。球体适合首屏的探索入口；正文区域继续使用 [Material Design 设计方案](../../Material_Design/Material_Design_设计方案.md) 中的稳定表面、文字层级和交互规则。

## 把视觉要求变成具体规则

“神秘”“有能量”“有生命感”需要进一步落实为可调整的形状和运动。

| 视觉要求 | 可控制的规则 | 检查重点 |
|---|---|---|
| 不规则 | 分区大小不同，孔洞有宽口、细缝和不同方向 | 是否仍能看出整齐重复的网格 |
| 镂空 | 分别定义分区外轮廓与孔洞轮廓 | 孔洞是否与外壳形成明确的边界 |
| 透光 | 孔洞内有半透明彩色膜，内部光源可通过膜显现 | 是否有内外层次，而非仅有表面色块 |
| 金属感 | 骨架保持深色，孔洞边缘有细窄高光和暗面 | 亮度是否集中在边缘，骨架是否仍可辨认 |
| 能量感 | 内核较亮，膜有颜色变化，外部光晕克制 | 是否能分辨光源、受光表面和外围光晕 |
| 生命感 | 多轴旋转、局部扭曲、轻微起伏使用不同节奏 | 运动是否连续，是否过于机械或喧闹 |

每轮调整聚焦一个问题。例如，孔洞过于整齐时先改几何；骨架被光淹没时先改亮度关系。这样更容易判断修改是否有效。

## 现有实现的几何方法

### 不规则分区保持连续

`geometry()` 先利用黄金角在球面分布点，再加入位置扰动。随后通过凸包面得到球面上的公共角点，将相邻角点按各分区的局部方向排序，组成类似球面 Voronoi 的分区。

这种方法兼顾两个目标：分区有变化，相邻分区又能共享边界。变形时，对公共边界使用相同的坐标变换，骨架就能保持连接。

当前普通模式使用 94 个分区，低性能模式使用 70 个。几何在初始化时构建一次；增加分区数量仍会提高初始化和逐帧绘制成本，需要单独测量。

### 孔洞同时改变大小和长宽关系

每个分区都有外轮廓和孔洞轮廓。孔洞由分区中心向边界插值得到，再按方向压缩，并加入轻微轮廓扰动。

当前约每六个分区中有一个较小孔洞；其他孔洞也会采用不同的压缩程度。大开口和细长缝隙并存，让外壳具有疏密变化。

| 参数 | 当前取值 | 控制对象 |
|---|---|---|
| 分区数量 | 普通 94，低性能 70 | 外壳细节密度 |
| 几何随机种子 | 4817 | 在相同模式下重现相同分区 |
| 小孔洞 `opening` | 约 0.46 至 0.67 | 从分区中心向边界插值的幅度 |
| 大孔洞 `opening` | 约 0.90 至 0.985 | 从分区中心向边界插值的幅度 |
| 孔洞方向与压缩 | 每个分区分别设置 | 孔洞的朝向和长宽关系 |
| 路径圆角系数 | 约 0.40 至 0.49 | 折角过渡的柔和程度 |

`opening` 是插值系数，不代表整个球体的开孔面积百分比。这些数值是当前效果的起点，改变球体尺寸和背景后仍需重新观察。

## 现有实现的材质与空间层次

### 分开绘制骨架和透光膜

`drawCell()` 先将绘制区域裁剪到孔洞内部，填入彩色渐变膜、柔和亮斑和移动曲线。随后绘制分区外轮廓与孔洞组成的复合路径，通过 `evenodd` 填充规则让金属外壳避开孔洞。

孔洞里实际绘制了透光膜，因此它具有自己的颜色与透明度。骨架另外使用深色渐变，孔洞边缘再加细窄高光。膜、骨架和边缘各有明确的亮度角色。

调色时优先保留这种关系：内核最亮，透光膜提供彩色变化，骨架较暗，边缘高光细而清楚。扩大所有光晕或同时提亮所有表面，容易削弱层次。

### 用三维坐标控制二维绘制

球体使用二维 Canvas 绘制，但几何点保留三维坐标。`deform()` 处理旋转与形变，`project()` 使用透视关系把点映射到画布上。

`render()` 按分区中心的深度排序，主要次序为：背面骨架与透光膜、内部光源与能量曲线、正面骨架与透光膜，最后补充前景尖刺和反光。前后遮挡共同形成空间感。

这属于近似的遮挡与光效模拟。复杂穿插、真实折射或精确环境反射需要另外评估具备深度缓冲和相应材质能力的三维渲染方式。

## 现有实现的运动方法

`deform()` 将多个不同频率和相位的正弦变化叠加到坐标上，包括局部径向起伏、随位置变化的扭曲、三个方向的轻微伸缩，以及速度有变化的多轴旋转。透光膜的颜色方向、膜内曲线和内核亮度也各有缓慢变化。

整体旋转让观众看到前后结构，局部形变让轮廓持续变化，内部光线运动则增加深度。调试时应先分别观察，再组合，避免多个强烈运动同时争夺注意力。

当前绘制节奏的目标为普通模式 30 帧每秒、低性能模式 24 帧每秒，实际帧率取决于设备和页面负载。像素比上限分别为 2 和 1.5；两种模式使用不同的分区数量和膜内曲线数量。

渲染器提供 `setActive()` 和 `setReducedMotion()`。页面可以据此控制首屏可见时的活动状态，并在页面隐藏或减少动态模式下停止持续绘制。具体默认播放策略由页面决定；装饰光晕和网格继续遵循设计规范的静态默认规则。

## 人物素材与球体分别制作

人物使用透明背景图片，手心保持空白，球体由独立 Canvas 绘制。这样可以分别调整人物、球体的悬浮位置、尺寸和光效，并给球体设置独立的点击区域。

已有 [人物素材提示词](../托举人物/人物素材提示词.md) 明确要求保留手势、人物构图和真实透明背景，手心不生成球体。复用时先确认手心锚点，再确定悬浮高度；桌面与手机分别检查托举关系。

若要让光落在手掌上，可使用独立的局部光层。控制光的范围和强度，让手掌仍有纹理，人物轮廓仍可辨认。

## 复用流程

1. **先确定静态轮廓。** 在简单背景上观察球体大小、疏密和孔洞形状，暂时关闭持续动画。
2. **检查镂空结构。** 调整分区数量、开口幅度与压缩方向，确认骨架连续、孔洞有变化。
3. **建立材质关系。** 依次加入暗骨架、透光膜、内核和边缘高光，逐层观察各自的贡献。
4. **加入运动。** 先观察整体旋转，再加入局部形变与膜内光线运动；保持慢速、低幅度。
5. **与场景对齐。** 检查手心锚点、悬浮高度、背景对比度，以及不同窗口下的裁切。
6. **接入交互并验证。** 检查球体按钮、展开入口、Esc 收起、键盘焦点、减少动态模式和低性能模式。

比较方案时，固定随机种子、窗口尺寸、像素比、运行模式和动画时间。当前初始时间为 `2.5`，可用于对照初始静帧；旋转后的不同朝向不宜直接当作参数改善的证据。

优先保存可复现的静帧、参数和短预览。达到预期后，再组合进完整页面并检查滚动时的绘制负担。

## 复用时的排查顺序

| 表现 | 优先检查 | 调整方向 |
|---|---|---|
| 表面像普通规则网格 | 分区是否重复、孔洞是否过于等大 | 增加有控制的位置扰动，改变开口和压缩方向 |
| 球体亮成一团 | 骨架、膜和内核是否同时过亮 | 恢复暗骨架，缩小光晕，让亮度集中于内核与细边缘 |
| 孔洞像表面贴纸 | 外壳是否真正避开孔洞，膜是否有透明度 | 分别绘制孔洞膜与镂空骨架，检查复合路径填充 |
| 转动时像平面图案 | 是否只有平面旋转，前后次序是否正确 | 检查三维坐标、透视投影与深度排序 |
| 运动过于机械 | 所有变化是否使用相同频率和相位 | 分开设置旋转、形变与内部光线的节奏 |
| 人物与球体脱节 | 手心锚点、悬浮高度、局部受光是否一致 | 分别调整位置与光层，再检查不同窗口 |
| 手机或滚动时卡顿 | 是否持续绘制不可见内容，细节和像素比是否过高 | 先暂停无须活动的绘制，再减少分区、曲线与像素比，并实际测量 |

## Git 记录的范围

Git 历史没有保留首次提交前的失败版本，因此无法从提交记录确认“第一次失败，后来成功”的具体原因。上面的排查顺序是后续设计建议，不作为早期失败过程的复盘结论。
