# 深色科技演示设计规范（Material Design 3 启发）

本方案用于 AI、技术报告与数据演示，覆盖固定幻灯片、网页演示控制器和移动端阅读。采用深蓝背景、紫蓝强调色、圆角卡片和克制的科技装饰，统一视觉、组件、交互和交付规则。

## 0. 范围、依据与使用方式

### 0.1 与 Material Design 的关系

**本设计属于 Material Design 3 启发的自定义演示主题。** Material 官方按 Foundations、Styles、Components 组织设计体系；本规范借鉴其颜色角色、文字角色、组件与状态的组织方式。[Material 官方介绍](https://m3.material.io/get-started)

紫蓝渐变、光晕、网格与毛玻璃是可选的科技装饰；界面层级由语义色彩、排版、布局和交互规则共同组织。

本规范依据截至 **2026-10-09** 查阅的官方资料。M3 Expressive 是 Material 3 的扩展。本项目默认克制的运动表达；后续采用 Expressive 时，应另外记录平台、实现版本及运动参数。

### 0.2 规范约定

本方案将 Material 的设计组织方法应用于科技演示。颜色数值、画布坐标、字号、断点、组件尺寸和特效均为本方案的自定义参数。引用的官方资料用于说明角色语义与设计原则。

使用时先选择交付形态，再选页面模式和组件；同类内容保持统一角色。实际交付前按第 13 节检查目标环境中的阅读和操作效果。

### 0.3 三种交付形态

| 形态 | 适用规则 | 实现边界 |
|---|---|---|
| 原生 PPT／PDF | 色彩、排版、空间、形状、层级、图表、文案与静态阅读顺序 | 不照搬 CSS、悬停态、网页键盘事件或 `backdrop-filter` |
| 网页演示 | 固定画布，加画布外的导航、目录、主题与阅读模式控制 | 需要完整交互、键盘、焦点和运行时状态 |
| 网页阅读 | 内容按窗口重排，图表附摘要和可读数据 | 不把整张幻灯片缩成手机上的小图片 |

文中“必须／不得”是本项目验收条件；“建议”是默认选择，例外应记录原因。WCAG 条款用于网页交付；原生演示参考其可读性原则，还需使用目标应用的可访问性检查。

## 1. 设计原则与气质

**目标：让观众快速读懂技术结论、证据与比较关系。** 科技感服务于内容层级。

| 原则 | 具体规则 | 验收方式 |
|---|---|---|
| 结论优先 | 每页一个核心问题；标题优先表达结论；详细证据放图表或附录 | 去掉装饰后，仍能识别标题、结论和证据 |
| 层级稳定 | 同一角色在全稿中使用同一字号、颜色角色和位置规则 | 同类页面逐页对比 |
| 克制强调 | 每页一个主要视觉重点；成功、警告与错误颜色只表达相应语义 | 检查是否出现多个互相竞争的强调区 |
| 可读优先 | 放不下时先删减、分组或拆页，再调整版式 | 不用 11–14px 小字承载演示核心信息 |
| 表达可信 | 展示来源、单位、评估条件和不确定性；装饰不暗示不存在的精度或交互 | 数字、排名和标签都有定义或来源 |

### 2.3 对比度要求

所有信息文字默认达到 **4.5:1**。按 W3C 的 sRGB 相对亮度公式计算不透明纯色配对，并使用未舍入的数值判定。[WCAG 文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

本方案两套主题的表面文字、链接、强调色及反馈容器文字配对均达到 4.5:1；所检查集合的深色主题最低约 5.74:1，浅色主题最低约 5.28:1。使用时仍需检查透明背景、渐变、图片和状态层合成后的实际对比度。

WCAG 对符合“大文字”定义的文字允许 3:1；本方案核心信息仍统一采用 4.5:1。必要控件图形、可辨认状态和信息性图形按适用条件达到 3:1；纯装饰与禁用控件按对应条件处理。[非文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)

### 2.4 渐变、透明度与主题切换

- 品牌紫蓝渐变为 `135deg, #667EEA → #764BA2`；粉紫渐变为 `#8B5CF6 → #EC4899`。
- 渐变用于封面、章节或装饰带。正文、数据表和操作控件默认使用不透明语义表面。
- 透明卡片及渐变文字需检查所有实际背景位置，不能仅测平均色或两个端点就宣布通过。
- 浅色主题按完整角色表切换，同时关闭深色光晕和毛玻璃装饰。不得只替换两个背景色。
- 成功、警告、错误和等级信息同时有文字或图标；不得仅靠颜色区分。[WCAG 颜色使用](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)

## 3. 字体与排版

Material 的基础文字角色包括 Display、Headline、Title、Body、Label。本项目借鉴角色命名，采用适合中文演示的自定义字号；下表不是官方 M3 字号表。[Material 字体使用](https://m3.material.io/styles/typography/applying-type)

### 3.1 字体选择

网页默认字体栈见配套 CSS。中文优先考虑实际可用的 Noto Sans SC、苹方和微软雅黑；西文可用 Roboto 或系统无衬线字体。必须检查混排后的基线、换行和数字宽度。

原生 PPT 必须明确指定字体，不能使用 CSS 回退栈。优先选择交付设备已安装的中文字体；允许且受目标格式支持时嵌入字体。导出前在目标应用检查替换字体、缺字与溢出。

字重术语统一为：400 Regular、500 Medium、600 Semibold、700 Bold、900 Black。字体没有对应字重时，不把软件合成的粗体当作字体已有字重。

### 3.2 固定 960 × 540 画布的文字角色

| 项目角色 | 字号 | 字重 | 行高 | 使用条件 |
|---|---|---|---|---|
| display-cover | 56px | 700 | 1.2 | 封面短标题，最多两行 |
| display-section | 48px | 700 | 1.2 | 章节标题，最多两行 |
| headline-page | 36px | 700 | 1.2 | 内容页标题，默认一行；长标题另选布局 |
| title-card | 24px | 600 | 1.3 | 卡片或图表标题，最多两行 |
| body-main | 24px | 400 | 1.5 | 投影场景核心说明，优先使用 |
| body-support | 20px | 400 | 1.5 | 表格、支持说明和较密集内容 |
| label | 18px | 600 | 1.3 | 标签、页内按钮和短分类 |
| caption | 16px | 400 | 1.5 | 来源、页码和辅助元信息；不承载关键结论 |
| data-value | 48px | 600 | 1.1 | 核心指标；使用等宽数字特性 |

演示信息文字最低使用 16px；核心说明优先 24px，支持说明优先 20px。现场投影需要从实际观看距离检查，必要时继续放大字号或拆页；纯色对比度通过不等于投影可读。

### 3.3 排版行为

- 中文默认 `letter-spacing: 0`，不全局套用 2px 字距。品牌短标签可以单独调整，但必须检查换行。
- 长段落使用 Body；标题不使用正文行高；每个角色只有一个默认行高，避免样式表与组件表冲突。
- 正文左对齐；封面、章节和独立核心数值可居中；比较表中的数值右对齐。
- 数字使用 `tabular-nums`；同一列统一单位、精度、小数位和缺失值标记。
- 重要标题、正文、图表标签不截断。移动端换行或拆分；省略号仅用于有完整内容入口的辅助列表。
- 网页阅读正文默认 18px、最小信息文字 16px，使用相对单位支持文字放大；演示画布字号不直接当作网页阅读字号。

## 4. 空间、网格与页面布局

### 4.1 单位与间距尺度

本方案采用 **4px 细分尺度，常用间距优先取 8px 的倍数**。这是项目选择，不表述为 Material 所有场景都必须遵守的固定尺度。

| token | 值 | 使用条件 |
|---|---|---|
| space-0 | 0px | 无额外间距 |
| space-1 | 4px | 图标或微调 |
| space-2 | 8px | 图标与短标签、紧凑元素 |
| space-3 | 12px | 紧凑控件内部 |
| space-4 | 16px | 小卡片、紧凑段落间距 |
| space-5 | 20px | 可选中间档位；默认优先 16 或 24 |
| space-6 | 24px | 标准卡片内边距、主列间距 |
| space-8 | 32px | 内容分组 |
| space-10 | 40px | 大区块分隔 |
| space-12 | 48px | 画布安全边距 |
| space-16 | 64px | 封面或特殊大间距 |

布局中的特殊间距应从以上尺度中选择，并记录适用场景。

### 4.2 固定画布与安全区

网页演示设计画布为 **960 × 540px，16:9**。原生 PPT 采用 16:9 页面，以设计坐标进行比例映射；CSS px 与 PPT pt 不直接按 1:1 处理。

| 区域 | 标准坐标／尺寸 | 说明 |
|---|---|---|
| 安全区 | x = 48…912，y = 48…492 | 宽 864、高 444 |
| 内容页标题 | x = 48，y = 48，宽 864，高约 44 | 一行 36px 标题 |
| 主内容区 | x = 48，y = 120，宽 864，高 324 | 超出则换布局或拆页 |
| 页脚 | x = 48，y = 468，宽 864，高 24 | 来源左对齐、页码右对齐 |

封面与章节页可使用专属布局，但其重要文字仍在安全区内。网页控制器位于画布外，不覆盖页脚。内容页默认内容宽度统一为 864px；专属布局另行规定局部区域宽度。

### 4.3 列布局与信息密度

标准列间距 24px；在 864px 内容宽度下：

| 布局 | 单列宽度 | 适用场景 |
|---|---|---|
| 单列 | 864px | 图表、流程、主要结论 |
| 两列 | 420px | 比较、文字与证据配对 |
| 三列 | 272px | 三个简短要点或指标 |
| 四列 | 198px | 短指标、数字和短标签；不放长段落 |

标准卡片内边距 24px，小卡片 16px；内容组之间至少 24px。标题与支持说明之间默认 8px。

同页核心要点建议不超过三个；放不下时按“删减重复 → 合并分组 → 改布局 → 拆页”处理，不靠缩小核心字号解决。长文本卡片外宽小于 240px 时，不使用多段正文。

### 4.4 页面模式

| 模式 | 必备结构 | 使用限制 |
|---|---|---|
| 封面 | 标题、主题说明、作者或机构、日期 | 可有品牌渐变；不放大表格 |
| 章节 | 章节编号、标题、可选一句引导 | 作为节奏分隔，装饰不传递数据 |
| 结论＋证据 | 一句结论、主图／主表、来源 | 默认技术报告模式 |
| 指标概览 | 最多四个短指标、单位、统计条件 | 长说明改为两列或三列 |
| 比较／流程 | 比较维度或步骤、解释、结论 | 不混用互不相关的评价尺度 |
| 附录／来源 | 方法、详细表、出处与日期 | 与主稿共享文字和表面角色；密集内容拆页 |

Material 提供跨窗口布局的模式；本文件的 16:9 页面坐标和页面模式是演示场景的扩展。[Material 布局示例](https://m3.material.io/foundations/layout/canonical-examples/overview)

## 5. 形状、边框与层级

### 5.1 形状尺度

| token | 值 | 使用条件 |
|---|---|---|
| radius-none | 0px | 表格、画布、分隔区域 |
| radius-sm | 8px | 小型辅助容器 |
| radius-md | 12px | 列表项、小卡片 |
| radius-lg | 16px | 标准卡片 |
| radius-xl | 24px | 重点卡片、弹层、控制器 |
| radius-full | 9999px | 按钮和胶囊标签 |
| circle | 50% | 宽高相等的编号、头像 |

普通卡片采用 16px 圆角，重点卡片采用 24px；按用途选择档位。

胶囊采用 full 圆角，不假设写死 18px 就一定是高度的一半。装饰切角不替代容器边界，也不能影响点击区域。

### 5.2 边界

- 普通卡片可用 1px outline-variant 分隔；由于它可能很淡，不用它单独证明控件边界可辨。
- 需要识别的输入边界和状态标记使用 outline 或其他达到适用对比度的色。
- 焦点环使用独立 2px 轮廓和 3px 外间距，不被圆角裁切；不能只用阴影或变色表达键盘焦点。
- 列表中的主色侧条宽 4px，必须同时有文字或选中标记，避免仅靠颜色表达状态。

### 5.3 表面与阴影

| 项目层级 | 表面默认值 | 阴影 token | 用途 |
|---|---|---|---|
| base | surface | none | 页面与固定画布 |
| content | surface-container | shadow-card | 普通卡片；密集数据表默认无阴影 |
| raised | surface-container-high | shadow-raised | 重点卡片或浮动控制器 |
| overlay | surface-container-high | shadow-overlay | 目录弹层、帮助弹层 |

表面色、边界和遮挡顺序共同表达层级。阴影参数是项目值，不把任意 `box-shadow` 直接等同于 Material 的 elevation token。深色主题阴影较不明显，不能依赖加深黑色阴影来区分所有层级。

网页层叠顺序统一为装饰 0、内容 1、控制器 20、遮罩 30、弹层 40、反馈 50。装饰不得遮住文字或接收指针事件。

## 6. 图标、图像与科技装饰

### 6.1 图标规范

SVG 是文件格式，不代表图标风格统一。新网页控件默认选择 **Material Symbols Outlined**，图标外框 24 × 24px，视觉字重 400、grade 0、optical size 24；选中状态可填充，仍需文字或状态标记。所用资源必须确认实际支持这些参数。[Material Symbols 指南](https://developers.google.com/fonts/docs/material_symbols)

若使用自定义 SVG，统一 24 × 24 的 viewBox、约 2px 描边、圆端点和圆连接；不要同页混用不同风格的图标套装。图标与文字间距默认 8px。

| 图标用途 | 可访问性与行为 |
|---|---|
| 装饰图标 | 网页设为 `aria-hidden="true"`；原生演示标记为装饰 |
| 图标＋可见标签 | 使用可见标签作为控件名称，避免重复朗读图标 |
| 仅图标按钮 | 必须有准确的可访问名称；提示信息同时支持悬停和聚焦 |
| 状态图标 | 与“成功／失败／警告”等文字配合，不能只靠颜色 |

原生 PPT／离线网页应冻结图标文件，避免临场依赖远程字体加载。不得用 emoji 代替需要一致视觉表现的功能图标。

### 6.2 图片与插画

- 技术示意图优先使用可读矢量；截图保留其说明所需区域和出处，不添加改变证据含义的滤镜。
- 照片统一裁切比例，常规内容图 16:9，头像 1:1；不拉伸。
- 重要对象不被圆角或裁切遮挡。图片上的文字需有稳定底色，不把背景光晕当作对比度保护。
- 信息图提供替代说明；重要图表还需数据摘要或表格。记录素材来源、许可与必要署名。

### 6.3 装饰边界

| 效果 | 允许场景 | 默认规则 |
|---|---|---|
| 紫蓝渐变 | 封面、章节、品牌带 | 单页一个主要渐变区；不作为默认正文底色 |
| 光晕 | 封面或章节背景 | 默认最多两个；避免覆盖正文与图表 |
| 网格 | 简单科技背景 | 40px 单元、0.5px 线宽、0.08 透明度；视输出效果降低或关闭 |
| 毛玻璃 | 网页画布外控制器 | 默认关闭，开启时仍需可辨边界和稳定对比度 |
| 渐变文字 | 短装饰性标题 | 重要结论优先纯色；导出必须有纯色替代 |

柔和光晕使用径向渐变或模糊，并检查输出。`fill-opacity` 只影响填充，`opacity` 影响整个元素或组；应按目标选择，不能规定所有情况都只用前者。

本项目建议用独立的背景 SVG；下面是有效的径向渐变示例。重复使用时将 ID 做成页面唯一，避免 SVG 引用冲突。

```html
<svg viewBox="0 0 960 540" xmlns="http://www.w3.org/2000/svg"
     aria-hidden="true" focusable="false">
  <defs>
    <radialGradient id="cover-glow">
      <stop offset="0%" stop-color="#8B5CF6" stop-opacity="0.16" />
      <stop offset="100%" stop-color="#8B5CF6" stop-opacity="0" />
    </radialGradient>
  </defs>
  <circle cx="800" cy="80" r="200" fill="url(#cover-glow)" />
</svg>
```

毛玻璃依赖真实背景与浏览器支持；无 `backdrop-filter` 时使用不透明 surface-container。原生 PPT、PDF 或打印模式直接采用稳定表面，不声称 CSS 背景模糊可跨格式原样实现。

## 7. 组件规范与使用条件

本节是演示场景的组件契约。控件尺寸为项目值，不是对官方所有按钮规格的转录。静态 PPT 使用静态组件，不绘制让人误以为可操作的按钮。

### 7.1 卡片

| 变体 | 结构与样式 | 何时使用 |
|---|---|---|
| standard | 表面＋标题＋支持内容；16px 圆角、24px 内边距 | 普通要点和证据 |
| emphasized | primary-container 配对或重点表面；24px 圆角、24px 内边距 | 单页一个主要结论或指标 |
| outlined | 标准表面、1px outline-variant、无阴影 | 密集比较内容 |
| interactive | 卡片内容＋明确的主要链接或按钮 | 仅网页确有动作时使用；继承完整交互状态 |

普通卡片不显示手形光标、悬停放大或按下效果。存在多个动作时，各动作分别可访问，不把嵌套按钮放在整张卡片按钮里。

标题与支持内容间距 8px，内容组之间 16–24px。整组卡片顶部、标题基线与内边距一致，不用“高级卡片”这种无法说明用途的变体名称。

### 7.2 标签、徽章与编号

- 分类标签是静态说明；筛选标签才有选中、禁用和聚焦状态。不得把两者混称。
- 分类标签使用语义 container／on-container 配对；高度随文字和内边距增长，默认 18px 字号、上下 6px、左右 12px。
- S／A 等级保留金银方案时，分别使用 `#FFD700`／`#A0A0A0` 底和 `#1A1A1A` 字，并增加等级含义说明。等级不是 Material 的标准状态，也不自动等于成功或失败。
- 标签尺寸根据文字和内边距自适应，不用固定高度裁切内容。
- 编号圆为 44 × 44px 的静态图形，字号 20px；使用 primary-container／on-primary-container。若编号本身可点，其点击容器仍须满足控件尺寸要求。
- 徽章表示计数或状态，必须说明“计数对象”或“状态对象”，不能拿装饰徽章替代动作标签。

### 7.3 按钮与链接

| 变体 | 角色配对／外观 | 使用条件 |
|---|---|---|
| filled | primary／on-primary，full 圆角 | 当前区域唯一的主要动作 |
| tonal | secondary-container／on-secondary-container | 次要但需要清晰辨认的动作 |
| outlined | 透明底、on-surface 字、outline 边框 | 有边界的次要动作 |
| text | 透明底、link 或 primary 字 | 低强调辅助动作；不用于唯一关键入口 |
| icon | 24px 图标，至少 48 × 48px 容器 | 上一页、下一页等熟悉动作；有可访问名称 |

网页控件实际显示的目标区域默认至少 **48 × 48 CSS px**，文字按钮横向内边距 16px，按钮间距至少 8px；控件不随画布一起缩小。这是本项目较保守的触控目标，**不是 WCAG 2.2 AA 的 48px 强制条款**。WCAG 2.5.8 的最低要求为 24 × 24 CSS px，另有间距等例外；不得混淆。[目标尺寸要求](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

链接用于跳转，按钮用于执行操作。链接有下划线；按钮标签用动作动词，如“下载报告”“进入阅读模式”，不使用只有“确定”“点击这里”的模糊描述。

### 7.4 演示控制器

这是一组**演示操作控件**，不是 Material 中用于切换顶级页面的 Navigation bar。

必备内容：上一页、当前页／总页数、下一页。网页版按功能增加目录、阅读模式、主题、全屏。控件始终位于画布之外；手机版可分行，不覆盖内容。

| 情况 | 行为 |
|---|---|
| 第一页 | 上一页禁用；不默认循环到末页 |
| 最后一页 | 下一页禁用；不默认循环到首页 |
| 切页 | 更新页码、标题与活动页；画布外控件焦点保持稳定 |
| 打开目录 | 标记当前页；使用普通链接／按钮列表，除非确实实现了 tab 模式才使用 tab 语义 |
| 目录是模态弹层 | 焦点进入弹层；背景不可操作；Esc 关闭；关闭后回到触发控件 |
| 全屏请求失败 | 保留页面可用，显示“当前环境无法进入全屏”，不伪装为已经全屏 |

### 7.5 列表、表格和反馈

- 列表由编号或图标、标题、说明组成；至少 16px 内边距。固定画布主内容区默认最多三条简短列表，条间距 16px，内容较长则拆页。
- 表格有表头、单位、排序含义及数据来源。网页使用真正的表格语义；行高随换行增加，数值列右对齐。
- 信息、成功、警告、错误反馈都有短标题和必要的下一步。长错误不只放在转瞬即逝的提示条中。
- 加载态描述正在加载的对象；只在任务进行时显示进度。没有已知进度时，不编造百分比。
- 空态说明为何为空及下一步，例如“当前筛选没有结果。清除筛选后查看全部模型。”
- 下载失败、资源失败等错误保留重试或替代阅读入口，不清空已经可读的内容。

通用表单、开关和复杂菜单不是当前演示主题的必备组件。以后增加这些功能时，必须另补结构、状态、输入验证和可访问性契约，不能声称当前组件库已覆盖所有应用场景。

## 8. 交互状态与行为

Material 将交互状态纳入基础规则。本项目对实际可操作元素规定以下状态；静态装饰不套用交互状态。[Material Foundations](https://m3.material.io/foundations/)

| 状态 | 视觉反馈 | 行为／语义 |
|---|---|---|
| default | 使用组件默认配对 | 可操作名称和用途清晰 |
| hover | 使用当前前景色的 8% 状态层 | 仅具有精确指针的设备启用；不改变布局 |
| focus-visible | 2px 独立焦点环，外间距 3px | 键盘可见；即使同时 hover 或 pressed 也保留 |
| pressed | 前景色的 12% 状态层 | 短暂反馈；默认不缩放命中区域 |
| selected／current | container 配对＋文字、填充图标或标记 | 根据功能使用 `aria-pressed` 或 `aria-current` 等对应语义 |
| disabled | 较弱表现，仍可辨认 | 真正阻止动作；原生 disabled 或正确实现的 aria-disabled |
| loading | 进度图形＋“正在下载”等明确文本 | 阻止同一任务重复提交；保留稳定名称；必要时 aria-busy |
| error | error-container 配对＋错误说明 | 说明恢复方法；与对应任务关联 |

8%／12% 是项目示例状态层值，不宣称为所有 Material 组件或版本通用的官方常数。图标或控件的前景色用于状态层；焦点使用单独的 outline 色，以免深色按钮前景在外侧背景上不清晰。

状态组合规则：

1. 不可用／正在处理的操作不触发正常 hover 和 pressed；若用 aria-disabled 保留可聚焦入口，应同时阻止鼠标与键盘动作。
2. selected 是持续状态，hover 和 pressed 是短暂反馈，可以叠加但不抹掉选中标记。
3. focus-visible 独立保留，不用“点击后取消焦点”实现视觉清理。
4. 错误说明属于任务状态，不覆盖其他焦点反馈。

网页必须让全部操作通过键盘完成，并提供可见焦点。[键盘要求](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html)、[焦点可见要求](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html)

### 8.1 演示键盘与页面状态

- Tab／Shift+Tab 遍历控件；Enter／Space 按原生按钮方式触发。
- 演示模式可提供左右箭头、PageUp／PageDown 切页，Home／End 跳转首末页；不拦截输入框、可编辑区、弹层及阅读模式中的正常按键。
- 非活动幻灯片须同时退出指针操作、Tab 顺序和可访问性树；只设 opacity 或 pointer-events 不足以实现这一点。
- 提供用户触发切页后的简短页码通知，避免朗读整页或重复播报；正文仍按正常阅读顺序访问。
- 焦点若在即将隐藏的页面内容中，先移到新页面标题或稳定入口，再隐藏旧页；不得把焦点留在不可见内容里。
- 可用 inactive 页面的 inert／隐藏语义管理，但具体浏览器、辅助技术行为要实际验证。

## 9. 动效系统

### 9.1 官方体系与项目取值

目前 Material 官方说明了 M3 Expressive 的弹簧运动体系，区分空间运动与颜色、透明度等效果，并提供 standard 和 expressive 方案。本方案采用下表中的简单过渡参数。[Material Motion](https://m3.material.io/styles/motion)

本项目采用易于导出和克制表达的简单过渡，以下是**项目值**：

| token／场景 | 时长 | 属性与曲线 | 使用条件 |
|---|---|---|---|
| motion-fast | 160ms | opacity、color；ease-out | 控件状态变化 |
| motion-normal | 240ms | opacity、transform；ease-out | 目录或帮助弹层 |
| motion-slow | 320ms | opacity；ease-in-out | 手动幻灯片切换 |
| motion-none | 0ms | 无位移、无缩放、即时状态反馈 | 减少动态、打印与静态导出 |

动画的用途是说明状态和内容关系；不把所有组件都做成悬停放大，不对正文进行弹跳或连续闪烁。封面光晕和网格默认静止。

### 9.2 切页与中断

- 默认切页淡入淡出，不缩放整页文字；缩放只有明确表达用途时才作为例外。
- 新切页请求以最新目标为准，取消或重定向旧过渡，不排成长队列。
- 隐藏语义、焦点和过渡收尾必须共同管理。退出动画结束后再彻底隐藏旧页，不能先立即 `visibility: hidden` 再期待看见淡出。
- 不默认自动播放。若增加自动播放，提供显眼暂停、速度和停止入口，且不强制跟随用户手动阅读。
- `prefers-reduced-motion: reduce` 时移除位移／缩放和非必要过渡；原生 PPT 相应使用无动画或短淡化版本。

新增弹簧动效时，记录所用框架及版本、方案、空间／效果参数和中断规则，并重做性能与可访问性检查。不要通过简单替换 `ease` 名称来声称已经实现 Expressive。

## 10. 自适应与可访问性

### 10.1 演示模式和阅读模式

等比缩放解决“整张画布装得下”，重排解决“内容读得清”。两者采用不同规则：

| 情况 | 默认策略 |
|---|---|
| 宽屏演示 | 保持 960 × 540 设计坐标，按可用宽高等比缩放；控制器不缩放 |
| 窗口宽度小于 720px | 默认进入阅读布局，保留切换演示模式入口 |
| 演示缩放系数小于 0.75 | 默认提示或切换阅读模式；24px 核心正文此时已小于 18px |
| 阅读宽度 320–599px | 单列，16px 外边距，正文 18px；操作区换行 |
| 阅读宽度 600–899px | 默认一列；两个简短指标可并排，24px 外边距 |
| 阅读宽度至少 900px | 按内容选择一至三列，32px 外边距；长段落保持舒适行宽 |

以上断点是项目值，依据可用内容宽度而非设备名称；不声称等于 Material 所有平台的窗口分类。

演示缩放公式为：`scale = min(可用宽度 / 960, 可用高度 / 540)`。先从可用高度扣除画布外控制器和间距；若可用尺寸为零，暂不显示画布并等待重新测量，不能生成负缩放。缩放原点、居中以及占位容器的实际宽高必须同步管理。

布局应测量真实容器，扣除控制器实际高度与间距。媒体查询判断窗口大小，而被 transform 缩小的画布仍保留设计宽度，不能期望缩放本身触发内部网格重排。

### 10.2 阅读重排

- 阅读模式取消画布固定宽高和绝对定位，标题、主体、页脚按正常文档流排列。
- 四列指标在窄屏变为一列；长文本不得横向溢出。不得同时维持固定坐标又声称正文已经重排。
- 有必要二维结构的表格或图表允许局部横向滚动，并提供标题、摘要和键盘可访问的滚动区域；不能让整页都必须横向滚动。
- 在 320 CSS px 宽度检查阅读模式，在 200% 文字放大及典型 400% 页面缩放条件下检查内容和控件。二维表格等例外应明确范围，不把整套演示都视为例外。[WCAG 重排要求](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)

### 10.3 可访问性规则

| 项目 | 本项目要求 |
|---|---|
| 文字 | 普通信息文字至少 4.5:1；检查实际背景、文字放大与字体替换 |
| 图形和控件 | 必要边界、图形和状态按适用条件达到 3:1；装饰不冒充信息 |
| 操作 | 全部动作有键盘路径、可见焦点和准确名称 |
| 阅读顺序 | 标题 → 结论 → 证据 → 来源；视觉排列与语义顺序一致 |
| 页面状态 | 活动页可访问，非活动页不进入键盘和辅助技术阅读 |
| 弹层 | 焦点进入、背景隔离、Esc 退出、关闭后返回触发入口 |
| 颜色 | 数据和状态还通过文字、图形、线型或直接标签识别 |
| 动态 | 可减少动态；不默认自动播放，不制造持续闪烁 |
| 内容 | 信息图有替代说明，图表有结论摘要及可读数据来源 |
| 原生演示 | 使用目标应用检查阅读顺序、替代文字、标题、链接和字体 |

满足此表不自动等于“通过 WCAG 2.2 AA”。正式合规评估需要覆盖实际交付物适用的全部条款和完整操作流程。

## 11. 内容、文案与数据表达

### 11.1 界面文案

语气保持清晰、直接、克制；术语全稿统一，中英文第一次出现时解释。操作说明优先描述用户目标。

| 内容 | 推荐写法 | 避免的问题 |
|---|---|---|
| 动作标签 | “下载报告”“打开目录”“进入阅读模式” | “点击这里”“操作” |
| 加载 | “正在生成 PDF…” | 无对象的“处理中”，或虚假的精确进度 |
| 错误 | “PDF 生成失败。请重试，或使用阅读模式查看。” | 只说“错误”，或暴露内部堆栈 |
| 空态 | “当前筛选没有结果。清除筛选后查看全部模型。” | 空白页面或只显示“无数据” |
| 页面提示 | “第 3 页，共 12 页” | 没有上下文的“3/12”仅供辅助技术理解 |
| 排名结论 | “在所列基准与测试条件下排名第一” | 未限定条件的“全球最强” |

目录、页面标题、图表名称保持一致。日期采用明确的 `YYYY-MM-DD`；页脚区分“数据更新日期”“评估日期”和“演示制作日期”。

### 11.2 文字密度

- 标题表达本页核心问题或结论；正文不把标题换句话重复一次。
- 正文以短句和分组为主；每个卡片只承担一个要点，证据或限制紧随相关结论。
- 对图表能直接表达的比较，不重复写完整数字清单。完整明细放附录或可展开的阅读内容。
- 参考来源可缩短为可辨认的机构／文献名称与日期，但完整出处要可访问，不能藏在无法辨认的小字里。

### 11.3 技术评估与图表扩展规范

以下规则用于 AI／模型评估和技术报告中的数据表达。

| 内容 | 规定 |
|---|---|
| 图表系列 | 默认蓝 `#93C5FD`、紫 `#C4B5FD`、绿 `#6EE7B7`、粉 `#F9A8D4`；仅用于深色图表表面，浅色系列另外检查 |
| 系列识别 | 同一模型或类别在全稿保持一致；配合直接标签、点形或线型，不能只靠颜色 |
| 标题与坐标 | 标题说明比较对象；坐标轴注明指标和单位；图内信息字号默认不低于 18px |
| 数字 | 同一列统一精度和单位；缺失值写“未测／未公布”，不以 0 代替 |
| 轴与尺度 | 柱状图默认从零起；特殊范围、对数轴、截断轴必须说明，避免夸大差异 |
| 排名 | 说明指标方向、权重和并列规则；S／A 等级说明阈值和评估日期 |
| 比较条件 | 同页标明模型版本、数据集或基准版本、重要测试设置；不可比项分组解释 |
| 不确定性 | 有误差或波动时说明区间、样本量或重复次数；没有资料时不补造数据 |
| 来源 | 标明原始发布方、链接及更新日期，说明是否是自测或转引 |
| 阅读替代 | 图表附一句结论摘要，复杂图表提供可访问的数据表或说明 |

图表需要检查标签、显示环境与导出质量。浅色打印或会议室投影分别检查可读性。

## 12. 实现、资源与维护

### 12.1 token 的组织方式

设计值应在设计文件和实现之间共享。Material 将 tokens 纳入基础体系；本项目采用下面的组织结构来落实复用。[Material Foundations](https://m3.material.io/foundations/)

| 层 | 示例 | 使用者 |
|---|---|---|
| 原始值／品牌值 | brand-indigo = `#6366F1` | 调色盘与主题制定者 |
| 用途角色 | sys-color-primary、sys-color-on-surface | 主题与组件 |
| 组件别名 | button-filled-bg → sys-color-primary | 具体组件；确有差异时增加 |

组件不得到处复制 HEX、阴影或间距。品牌色修改时，需要重新检查角色配对、两种主题、装饰、图表和状态；不能只替换一个 `--color-primary`。

### 12.2 配套文件

- [Material_Design_演示主题.css](Material_Design_演示主题.css)：本项目的可复用主题值和基础组件样式；使用 `.material-tech` 作用域，避免影响其他页面。
- [交互球体设计经验](素材/交互球体/交互球体设计经验.md)：首屏球体的几何、材质、运动与素材拆分方法，以及复用流程和排查顺序。

CSS 是配套样式，不是完整演示应用。它不实现切页、焦点管理、缩放测量、加载任务、弹层或数据逻辑，也不自动修复缺少语义的 HTML。不能只接入 CSS 就宣布可访问性验收完成。

### 12.3 最小网页结构示例

```html
<main class="material-tech" data-theme="dark">
  <article class="md-slide" aria-labelledby="slide-title-1">
    <h1 id="slide-title-1" class="md-slide__title">本页核心结论</h1>
    <div class="md-slide__body">
      <section class="md-card" aria-labelledby="card-title-1">
        <h2 id="card-title-1" class="md-title-card">证据标题</h2>
        <p class="md-body">替换为本页需要展示的证据或说明。</p>
      </section>
    </div>
    <footer class="md-slide__footer">
      <span>来源：机构或文献，YYYY-MM-DD</span>
      <span>1 / 12</span>
    </footer>
  </article>
  <nav class="md-controller" aria-label="演示控制">
    <button class="md-button md-button--outlined" type="button" disabled>
      <span>上一页</span>
    </button>
    <span>第 1 页，共 12 页</span>
    <button class="md-button md-button--filled" type="button">
      <span>下一页</span>
    </button>
  </nav>
</main>
```

这段结构只展示样式和语义入口；数字是示例，不代表已存在 12 页。加入控制逻辑后才具有切页功能。设为 `data-theme="light"` 切换颜色，给主题容器增加 `is-reader` 类进入阅读样式；应用还需处理相应页面状态。

### 12.4 导出与降级

| 输出 | 必查项目 | 处理策略 |
|---|---|---|
| 网页 | 字体加载、离线资源、键盘、焦点、重排、主题、动态设置 | 冻结所需资源；视觉特效失效时使用稳定表面 |
| 原生 PPT | 页面比例、字体、图片、阅读顺序、动画支持 | 按设计坐标映射；用目标应用确认实际字号和位置 |
| PDF | 文字可选择、字体、链接、阅读结构与分页 | 采用支持相应结构的导出方式；导出后复查 |
| 打印 | 浅色角色、背景打印、细线、来源和分页 | 关闭光晕与毛玻璃；不依赖印不出来的背景 |
| 图片 | 分辨率和文字清晰度 | 可作为预览，同时提供可读原文或结构化替代 |

代码示例按 HTML 与 CSS 分开使用；各平台的视觉保真需检查实际输出。

### 12.5 维护与例外

- 方案版本为 2.0.0，主题样式与本文件保持版本一致。
- 主题、组件与设计文件变更同步记录“改动、原因、影响范围、验证结果”。更改尺寸或角色映射时检查引用组件。
- 例外记录具体页面／组件、旧值与新值、原因、影响和复查条件。不得把“特殊场景”作为长期无约束的借口。
- 项目作者负责更新规范，设计负责人确认视觉例外，实现负责人检查行为与兼容性；个人项目可由同一人承担。
- 将未来出现的输入框、筛选器、复杂图表等需求加入明确的扩展列表；不要提前声称已有全部组件。

## 13. 交付验收

### 13.1 制作和交付前检查

- [ ] 同类页面共享颜色、文字、间距和形状角色，没有未记录的任意值。
- [ ] 纯色、渐变、透明背景及所有实际状态的对比度满足适用要求。
- [ ] 960 × 540 布局无溢出；标题、正文、来源在安全区内，控制器不遮挡。
- [ ] 用真实字体和真实中文内容检查换行、替换字体、数字对齐及观看距离。
- [ ] 普通静态卡片不伪装为可交互；链接和按钮用途明确。
- [ ] 从首末页、目录、主题、阅读模式、全屏失败等路径检查边界状态。
- [ ] 全部网页操作可通过键盘完成；焦点可见；隐藏页和模态背景不可误操作。
- [ ] 320px 阅读布局、200% 文字放大与典型 400% 页面缩放可用；必要的二维滚动有替代说明。
- [ ] 减少动态模式可用；用户可停止任何新增的自动播放。
- [ ] 两种主题、图标／图片、图表来源、替代文字和阅读顺序已检查。
- [ ] 所需字体和图标在目标环境可用，离线使用场景已验证。
- [ ] PPT、PDF、网页或打印的实际交付格式已逐一检查，没有用一种输出结果替代另一种验收。

### 13.2 交付验收记录

每次交付记录实际检查的文件、应用或浏览器版本、字体、显示设备、主题、窗口尺寸、操作流程和检查结果。颜色计算用于验证配对；浏览器、辅助技术、投影、PPT 和 PDF 分别检查各自的实际输出。
